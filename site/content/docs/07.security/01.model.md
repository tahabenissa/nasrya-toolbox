## No implicit catalog from the current directory

The catalog decides what `Enter` runs, so a malicious `tools.yaml` in a CTF folder, a loot directory or a cloned repo is **ignored**. Winsploit tells you it skipped one, and you can opt in with `--catalog .\tools.yaml`.

Resolution order: `--catalog <path>`, then `%WINSPLOIT_CATALOG%`, then the one next to `winsploit.exe`, then the source checkout (dev builds), then `%APPDATA%\winsploit\tools.yaml`. The active path is shown in the console.

## Wrong binaries are blocked

[`verify:`](/docs/catalog/verify-and-notes) checks catch a same-named program earlier on `PATH`. A tool in the conflict state is never launched.

## Programs are found by PATH, never the current directory

Executables resolve through `PATH` × `PATHEXT` only. `.cmd` / `.bat` shims go through Rust's escaped `cmd.exe` path, so arguments can't break out into new commands.

## Arguments are parsed, not shelled

Quote-aware splitting builds a real argv. There is no command-string concatenation and no shell, so `&`, `|`, `>` and `%VAR%` in arguments reach the tool as plain text.

## Downloads are hash-pinned

Every manifest in [Winsploit's bucket](/docs/catalog/bucket) has a fixed URL and SHA-256. Install commands are checked to be free of `cmd` metacharacters before they run, and `cmd /D` skips any AutoRun commands from the registry.

## The web view can't widen anything

The [web view](/docs/web-view/security) is off by default, binds 127.0.0.1 unless you ask for LAN, needs a per-session token or an owner-approved guest, checks `Host` (IP literals only) and `Origin` + JSON on every POST, and accepts only the same actions as the terminal's keys. It has no endpoint that runs a command line or serves arbitrary files.

## Samples can run in a throwaway VM

[`S`](/docs/using/sandbox) runs debuggers and other reversing tools in Windows Sandbox: the tool and the sample are mapped **read-only**, one output folder is writable, and network, clipboard, GPU, audio, camera and printers are off (network can be turned on per run). Your profile, `AppData`, Scoop, `Program Files` and Windows can't be shared as the sample folder. Sandbox runs are terminal-only, so the web view can never pick host folders to map into a VM.

## The AI suggests, you run

The [agent](/docs/using/agent) (`a`) and the [side chat](/docs/using/chat) (`T`) get no tool execution. They name a catalog tool and arguments, which winsploit parses into a real argv and runs through the normal launcher (or, for the agent, puts in the args prompt for you to review), so every run still goes through the install, conflict and argument checks. The chat is terminal-only: no web action can open it or send to it. Its `chat-autorun` setting is off by default, because tool output is untrusted text that reaches the AI.

The Claude CLI is called **isolated**: no tools, no MCP servers, no hooks, no slash commands, no saved session, its own system prompt and a scratch folder. Without that it would inherit your own Claude Code permissions and hooks while reading untrusted tool output, and a hook could be hijacked by it. A CLI too old to support the isolation is refused, not used anyway.

What is sent to a provider has secrets masked (the `redact` setting). Analysing output or chatting sends text to the provider you picked; choose Ollama to keep it local.

## Secrets stay out of the pane and the logs

A tool's `secret_args:` in the [catalog](/docs/catalog/tools-yaml) (`-p`, `--password`, `"-H Authorization"`) are masked in the pane's `$` line and in the run log. So are `user:pass@` URLs, `Authorization` and `Cookie` headers, bearer tokens, `password=…` pairs, JWTs and well-known API keys, and what you type at a `Password:` prompt shows as `********`.

The [`redact`](/docs/reference/settings) setting picks how far this goes: `off`, `commands` (the default: command lines and typed secrets) or `all` (also secret patterns in the log's tool output). Tool output is verbatim by default, since it is evidence: a cracked credential is a finding. A password prompt is only noticed when the tool ends its line.

## Audit trail

Every run and install leaves a timestamped [log](/docs/using/logs): the command, all output, everything you typed, the exit code and when it happened.

::callout{type="warning" title="Authorized use only"}
None of this makes it OK to scan what you don't own. Only test systems you have **explicit written permission** to test.
::

## Reporting a vulnerability

Please report security issues privately through [GitHub security advisories](https://github.com/tahabenissa/winsploit/security/advisories/new) rather than a public issue.

## Requirements

| | |
|---|---|
| OS | Windows 10 or 11 (x64) |
| Package managers | [Scoop](https://scoop.sh). pipx is bootstrapped through Scoop the first time a Python tool needs it |
| To build | Rust 1.87 or newer ([rustup](https://rustup.rs)) |

## Option A: build from source

::code-group
```powershell [Build]
git clone https://github.com/tahabenissa/winsploit
cd winsploit
cargo build --release
.\target\release\winsploit setup --path --shortcut   # `winsploit` command + Start menu entry
```

```powershell [Update]
cd winsploit
git pull
cargo build --release
```
::

The binary is `target\release\winsploit.exe`. A dev build looks for `tools.yaml` in the source checkout, so it works from any directory.

`winsploit setup --path` adds that folder to your **user** PATH (no admin; run it again any time, it won't add it twice). Open a new terminal and type `winsploit` from anywhere: tools run in the folder you start it from, see [the working folder](/docs/using/running-tools#the-working-folder). Each `cargo build --release` updates the command; close Winsploit first, since a running copy locks the file. To undo it, remove the entry under *Edit environment variables for your account*.

`winsploit setup --shortcut` adds a **Winsploit** Start menu entry and a Windows Terminal profile, both with the cube icon (and Frost colours in Terminal). Search for it or pin it to the taskbar or Start; it opens Winsploit in a Terminal tab with the cube on it, and the tab title follows the [working folder](/docs/using/running-tools#the-working-folder). A program running in Windows Terminal always shows Terminal's own taskbar button, so pinning the Start menu entry is how the cube gets onto the taskbar. Run it again after moving `winsploit.exe`; delete the files it lists to remove it.

## Option B: a release zip

Tagging `v*` publishes a Windows x64 zip (`winsploit.exe` + `tools.yaml`) on the [Releases](https://github.com/tahabenissa/winsploit/releases) page. Unzip it anywhere and run `winsploit.exe`; the catalog next to the exe is found automatically.

::callout{type="note"}
The binary is unsigned, so Smart App Control may ask you to allow it. The current `v0.1.0` release predates most of what these docs describe, so build from source until the next tag.
::

## Where the catalog comes from

The catalog decides what `Enter` runs, so Winsploit is strict about where it reads it from. It uses the first one that exists:

1. `--catalog <path>`
2. `%WINSPLOIT_CATALOG%`
3. `tools.yaml` next to `winsploit.exe`
4. the source checkout (dev builds only)
5. `%APPDATA%\winsploit\tools.yaml`

It is **never** read from the current directory unless you pass `--catalog .\tools.yaml`. The active path is shown in the console. See the [security model](/docs/security/model) for why.

## Extra Scoop buckets

Pressing `i` adds any bucket a tool needs the first time it's needed. To add them yourself:

```powershell
scoop bucket add security https://github.com/opsqw/scoop-security    # nuclei, httpx, subfinder, katana, ffuf
scoop bucket add extras                                              # Sysinternals, jadx, Ghidra, x64dbg, …
scoop bucket add winsploit https://github.com/tahabenissa/winsploit   # gau, john, steghide, nikto, seclists-lite
```

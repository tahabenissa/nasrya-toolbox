## Add a tool

New tools are the easiest place to start:

1. Add an entry to `tools.yaml` (see [Adding a tool](/docs/catalog/adding-a-tool)).
2. If nobody packages it for Windows, add a hash-pinned manifest to `bucket/`.
3. Run `cargo test` and `winsploit list`.
4. Open a PR.

Please only add tools that **really work natively on Windows**, and use `note:` to document any caveats.

## Fix the docs

Every docs page has an **Edit this page on GitHub** link at the bottom. Pages are Markdown in `site/content/docs/`.

## Code changes

- Keep the [security invariants](/docs/security/model) intact: no implicit catalog from the current directory, real argv (never a shell string), PATH × PATHEXT resolution, a log for every run.
- Style goes through `theme.rs`, never hardcoded colors or glyphs. ASCII glyph mode must not emit box-drawing characters.
- A new user-facing action needs a key in the terminal **and** a control in the web view.
- `cargo fmt`, `cargo clippy --all-targets -- -D warnings` and `cargo test` should pass.

## Report a bug

Open an [issue](https://github.com/tahabenissa/winsploit/issues) with your Windows version, terminal, the command you ran and the relevant [log file](/docs/using/logs). For security issues, see [the security model](/docs/security/model#reporting-a-vulnerability).

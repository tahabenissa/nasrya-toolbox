## Unreleased

### Helpers

- [Challenge workspaces](/docs/using/challenges) (`C`): one folder per CTF challenge with its own logs, flags, files, notes, target and flag format; switchable from the browser too.
- [Recipes](/docs/using/recipes): ready-made commands for 17 core CTF tools, filled with the challenge's `{target}`, `{file}`, `{out}` and `{wordlist}`.
- [Windows Sandbox](/docs/using/sandbox) (`S`): run debuggers and other reversing tools in a throwaway VM, sample read-only, network off by default.
- [Flag catcher](/docs/using/flags): CTF flags in any output are highlighted, copied and saved to `flags.txt`; `F` lists them.
- [AI agent](/docs/using/agent) (`a`): Claude, Gemini, DeepSeek, OpenAI or Ollama reads the output and suggests next steps as catalog tools you review and run. `A` picks the provider and model.
- [Side chat](/docs/using/chat) (`T`): say what you want in plain language; the AI picks one catalog tool and shows the plan, `Enter` runs it. Terminal only; `chat-autorun` is opt-in.
- Clipboard copies use the Windows clipboard API instead of `clip.exe`.

### Web view

- The same live session in your browser: every terminal, installs, hash IDs, run logs. Start it with `w`, `--web` or the start-up menu.
- Owner sign-in by one-time token; Host, Origin and JSON checks on every request.
- LAN mode (`W`, `--lan`): guests over HTTPS with a one-time join key, let in by the owner as watch-only or full control.
- Desktop notifications, grid of terminals, find and copy in the browser.

### Dashboard

- Up to four tools at once, each in its own terminal, next to the always-open console. Grid view with `g`.
- Category tabs, and tools listed in several categories.
- Glow-bar selection, friendly status line, toasts and a first-run tour.
- Appearance panel (`t`): themes matching Claude Code's `/theme`, borders, ASCII glyphs, bold, docked or centered overlays.
- Tool list filter (`/`), key help overlay (`?`), args prompt with real line editing, history and paste.
- Built-in hash identifier (`h` / `winsploit hashid`).

### Catalog: 6 → :stat{k="tools"} tools

- Recon and web: gobuster, feroxbuster, httpx, subfinder, amass, katana, rustscan, gau, nikto.
- Reversing: radare2, upx, jadx, apktool, Detect It Easy, Cutter, x64dbg, dnSpy, Ghidra.
- Forensics, crypto, stego: exiftool, strings, Sleuth Kit, openssl, CyberChef, steghide.
- Python tools via pipx: arjun, dirsearch, wfuzz, commix, hashid, NetExec, RsaCtfTool, Volatility 3, ropper, pwntools, theHarvester, Sherlock.
- Passwords and data: John the Ripper (jumbo), ZAP, SecLists-lite wordlists.

### Engine

- pipx installs and `gui` / `web` / `dataset` launch modes.
- Winsploit's own hash-pinned Scoop bucket.
- `{scoop_app}` and `{app:NAME}` placeholders; automatic bucket add with `bucket/pkg` pinning.
- `verify:` impostor detection.
- Detection off the UI thread; PATH changes picked up live; `.cmd` / `.bat` shims launch correctly.

### Runner and output

- Each running tool gets its own stdin pipe.
- Streaming survives non-UTF-8 output; CR progress bars and ANSI codes are cleaned.
- Scrollback, find in output (`f` / `n` / `N`), per-run log files.

### Security and hygiene

- Secrets stay out of the pane and the run logs: catalog `secret_args:`, token and password patterns, masked password prompts, and a `redact:` setting (`off` / `commands` / `all`). The same masking applies to text sent to an AI provider.
- The Claude CLI is called isolated (no tools, MCP servers or hooks, its own system prompt), so it can't inherit your Claude Code permissions while reading untrusted output.
- A pure scope matcher (`scope.rs`) is in place for upcoming scope enforcement; nothing calls it yet.
- Faster detection (parallel `verify:` checks with a cache) and a notification with the run duration.
- Never loads `tools.yaml` from the current directory implicitly.
- Quote-aware argument splitting.
- Renamed from nasrya to **Winsploit**.

## The big picture

```text
tools.yaml ─► registry ─┬─► detect (PATH × PATHEXT + verify) ─┐
  (load + validate)     └─► install (scoop · pipx · buckets)  │
                                 └─► envpath (live PATH) ─────┤
                                                              ▼
           keys ──► app (state machine, App::apply) ◄── AppEvent channel
       web view ──►        │          │
                           ▼          ▼
                    ui (ratatui)   runner (spawn · stream · stdin · kill tree)
                                      └─► runlog (per-run logs)
```

## One loop, many workers

`App::run` redraws, drains an `mpsc` channel of `AppEvent`s, then polls the keyboard for 80 ms. Everything slow happens on other threads and reports back through that channel:

- `Output { sid, line }` and `Exited { sid, code }` from spawned processes
- `Detected(..)` from the off-thread detection pass
- actions and connection events from the web view

## Sessions

A `Session` is one terminal: output buffer, stdin pipe, scroll and search state, run log. The app holds the always-open console (id 0) plus :stat{k="slots"} tool slots. Events are routed by **session id**, never by slot, and ids are never reused, so late output from a replaced terminal is simply dropped.

## Rendering is a pure function

`ui::render` reads the app state and never mutates it. Input modes, overlays (appearance, help, tour) and confirmations all live in `App`. All styling goes through `theme.rs`: a semantic palette, a glyph set (Unicode or ASCII) and a border set.

## Terminal and web share one code path

Keys and web requests both become an `app::Action` and go through `App::apply`. Once per frame, `sync_web` mirrors sessions, toasts and state to every connected browser over Server-Sent Events. A test checks that every action has both a terminal key and a web control.

## Modules

| Module | Responsibility |
|---|---|
| `main.rs` | CLI entry point: TUI, `list`, `hashid`, flags |
| `registry.rs` | Loads and validates the catalog, resolves its path, expands placeholders |
| `detect.rs` | PATH × PATHEXT detection and `verify:` impostor checks |
| `install.rs` · `scoop.rs` | Install planning (Scoop / pipx, bootstrap), buckets, app folders |
| `envpath.rs` | Picks up PATH changes made after start-up |
| `args.rs` · `editor.rs` | Quote-aware argument splitting · line editor and history |
| `hashid.rs` | Built-in hash identifier |
| `runner.rs` · `session.rs` · `runlog.rs` | Spawn, stream, stdin, kill tree, output cleaning · terminals · logs |
| `app.rs` · `ui.rs` · `theme.rs` · `banner.rs` | State machine · rendering · appearance · splash |
| `web.rs` | The web view: HTTP + SSE server, sign-in, guests |
| `sandbox.rs` | Windows Sandbox runs: locate the tool, safety checks, `.wsb` generation |
| `flags.rs` | Flag catcher: finds CTF flags in output lines |
| `workspace.rs` | Challenge workspaces: folders under `%USERPROFILE%\ctf`, `challenge.yaml`, the remembered active one |
| `recipe.rs` | Recipe placeholders: validation and filling (one quoted argument per value) |
| `tls.rs` | The LAN web view's HTTPS: a self-signed certificate kept in `%APPDATA%\winsploit`, with its fingerprint printed in the terminal |
| `agent.rs` | AI agent: prompt, provider calls (isolated claude CLI or OpenAI-compatible HTTP), parsing suggestions |
| `chat.rs` | The side chat's pure part: transcript, plan states, prompt, tolerant reply parsing, wrapping |
| `redact.rs` | Secret redaction for the pane, logs and text sent to an AI: catalog `secret_args:`, token and password patterns, password prompts |
| `scope.rs` | Pure scope matcher (target × scope → in / out / unknown): IPs, CIDRs, host wildcards, URL prefixes, IDN. Not wired in yet |
| `bucket_tests.rs` | Validates every `bucket/` manifest against the catalog |

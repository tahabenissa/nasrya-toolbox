Every run and every install is written to its own file:

```text
%LOCALAPPDATA%\winsploit\logs\<UTC timestamp>-<tool>.log
```

The path is printed at the start of the run (`:: log: …`).

## What's in a log

- the exact command line that was launched
- where it was started from (terminal or browser)
- **all output**, including lines that scrolled out of the in-memory buffer
- **everything you typed** into the tool (`> your line`)
- the exit code (or that it was stopped) and timestamps

That makes a log usable as evidence in a report: what ran, against what, when, and what came back.

## Secrets

The command line in a log (and in the pane's `$` line) has secrets masked: the values of a tool's `secret_args:`, `user:pass@` URLs, `Authorization` / `Cookie` headers, bearer tokens and `password=…` pairs. What you type at a password prompt is logged as `********`. Tool output stays verbatim by default, because it is evidence; set `redact: all` in [settings.yaml](/docs/reference/settings) to mask secret patterns in the output too, or `redact: off` to turn masking off.

## From the web view

Each terminal in the [web view](/docs/web-view/overview) has a **Log** button that downloads that run's log. Only logs Winsploit registered for an open terminal can be downloaded; the web view can't read any other file.

`Enter` on a tool with recipes shows them, **already filled in** from the active [challenge](/docs/using/challenges). Pick one, check the arguments in the prompt, and `Enter` runs it. The last row, **custom**, is the tool's usual example arguments.

:stat{k="recipeTools"} core CTF tools come with 2 to 4 recipes each, for example:

| Tool | Recipes |
|---|---|
| nmap | quick, full, udp, vuln scripts |
| ffuf | dirs, dirs + extensions, recursive |
| sqlmap | test the url, list databases, crawl forms |
| hashcat | wordlist (auto mode), identify the hash type, show cracked |

The rest are in [`tools.yaml`](https://github.com/tahabenissa/winsploit/blob/main/tools.yaml).

## Placeholders

| Placeholder | Becomes |
|---|---|
| `{target}` | The challenge's target: IP, host, URL or `nc host port`. Asked for once, then saved in the challenge |
| `{file}` | The challenge file. Asked for when there are several; a file from elsewhere is copied into `files\` |
| `{out}` | The challenge's `out\` folder, for files tools write (`nmap -oN`, `upx -o`…) |
| `{wordlist}` | SecLists-lite `common.txt`, or the challenge's own wordlist |

A missing value is asked for first and kept, so you only type a target once per challenge.

**Each value becomes exactly one argument.** A path with spaces stays whole, and a target can never smuggle in extra flags.

## In the web view

Next to the arguments box, a **Recipe…** menu fills in the arguments. Values the challenge doesn't have yet are left as `{target}`-style gaps for you to replace. Try it in the [live demo](/demo/).

## Writing recipes

Add `recipes:` to a catalog entry. See [tools.yaml](/docs/catalog/tools-yaml).

```yaml
  - name: nmap
    # ...
    recipes:
      - { name: quick, args: '-sV -T4 {target}' }
      - { name: full,  args: '-p- -sV -sC -T4 {target} -oN {out}\nmap-full.txt' }
```

Write placeholders **unquoted**: Winsploit quotes the values for you. The catalog check rejects unknown or quoted placeholders and duplicate recipe names.
